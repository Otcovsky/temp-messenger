# Нагрузочные тесты

`tm_load.py` — нагрузка на ретранслятор (k6 не умеет Ed25519, без него не пройти авторизацию на `/ws`).
`server_mon.py` — замеры на сервере во время теста (CPU, память, дескрипторы uvicorn, соединения к бэкенду).

Запуск с сервера `loadtest` (нужны `python3-websockets`, `python3-aiohttp`, `python3-cryptography` из apt):

```bash
python3 tm_load.py chat --clients 90 --ramp 45 --steps "1:30,3:30,6:30,10:30,15:30" --out steps.json
python3 tm_load.py blob --workers 2 --blob-size 4194304 --duration 60 --out blob.json
python3 server_mon.py 250 5        # на сервере мессенджера, параллельно с тестом
```

Клиенты чата разбиты на пары, каждый шлёт собеседнику сообщения (пуассоновский поток) и подтверждает
полученные. В конце каждый снимает свой ящик (`unregister`), файлы удаляются через `done` — на сервере
ничего не остаётся. Тест сам останавливается при массовых отказах подключения или p95 доставки выше порога.

Ограничения nginx на один IP (`/etc/nginx/conf.d/tm-limits.conf`): 100 соединений, `/ws` 2 в секунду
(запас 30), `/blob/` 5 в секунду (запас 50). С одного адреса больше 100 соединений не открыть.

## Найденное

1. **429 на `done` оставляет файл на сервере на 7 дней.** Так случилось в первом прогоне теста:
   64 файла (256 МиБ) остались, квота ключа кончилась, следующие загрузки получили 507. Скрипт
   исправлен (повтор при 429), остатки удалены. **В клиенте то же самое:** `blobDone`
   (`client/src/transport/blobs.ts`) игнорирует ответ, а `refusal()` считает 429 окончательной ошибкой
   (`permanent = status < 500`), поэтому ни загрузка, ни скачивание при 429 не повторяются. На практике:
   открыть чат, где больше ~25 файлов (GET + done на каждый — больше запаса 50), или отправить
   несколько альбомов подряд — часть файлов не скачается/не отправится с «Сервер отклонил файл (429)»,
   а недоскачанные останутся на сервере и в квоте отправителя.
   **Исправлено** (ветка `claude/blob-429-retry`): 429 — временный сбой, загрузка и скачивание
   повторяются через 20–40 с (случайная пауза, чтобы файлы альбома не шли разом), `done` повторяется
   при 429/5xx/обрыве с паузами 1…32 с. Тесты в `client/src/transport/blobs.test.ts`.
2. **Потолок одновременных соединений не проверен** — с одного IP больше 100 не открыть, а снять лимит
   для адреса loadtest не удалось (изменение nginx отклонено автоматической проверкой безопасности).
   По конфигурации потолок около **700–750 WebSocket**: `worker_connections 768` × 2 процесса nginx,
   каждое WebSocket-соединение занимает в nginx два (клиент + бэкенд); у uvicorn
   `LimitNOFILE` 1024. Поднять: `worker_connections 4096` + `worker_rlimit_nofile 8192` в nginx.conf,
   `LimitNOFILE=65536` в drop-in юнита.
3. Сам ретранслятор держит обычную нагрузку с большим запасом: если человек шлёт сообщение раз в
   минуту, 1800 сообщ./с — это десятки тысяч активных собеседников; раньше упрёмся в пункт 2.
